# Tekka Sushi — QA Round 2 — 2026-05-08

## Scope

Second QA pass focused on mobile behavior and conversion visibility after QA1 fixes.

## Checks run

- `npm run typecheck` — passed
- `npm run build` — passed
- Playwright 390px mobile checks for `/`, `/menu`, and `/reservation`
- DOM width check: each tested route had `documentElement.scrollWidth === 390`

## Findings

1. **Mobile hero still consumed too much early vertical space.**
   - The Qitchen default 60vh mobile hero delayed the conversion/content area too much for a neighborhood order-forward sushi site.
2. **Conversion path needed route-level verification.**
   - Visit and menu pages needed explicit mobile evidence that order/call paths were present after layout fixes.

## Fixes applied

1. Reduced mobile `PageHeroSplit` hero height from 60vh to 48vh while preserving desktop Qitchen split.
2. Captured 390px mobile screenshots for home, menu, and visit pages after the conversion/mobile fixes.
